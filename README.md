# Navier–Stokes: paper-to-Lean statement audit (unreviewed)

> **Unreviewed machine audit.** AI agents produced every verdict; no mathematician has checked any of it.

This repository records an agent audit of OpenAI's *Finite time blowup for Navier–Stokes* (166 pages) against its Lean formalization, [openai/NavierStokesAndEuler](https://github.com/openai/NavierStokesAndEuler) at commit `f9e8bc5b38b6e212696e8a30e3e91517af887bbd`. For each of the paper's 80 numbered items and 762 displayed equations, it names the Lean declarations that state it and records whether they say what the paper says. It has three parts:

- [Literature Links](https://github.com/mathlib-initiative/literature-links) annotations, which link each item and display to its declarations;
- a PDF overlay viewer, generated by the [formal-companion](https://github.com/mathlib-initiative/formal-companion) tool;
- a report, [`REPORT.md`](REPORT.md).

**Scope.** The agents read the Lean source at `f9e8bc5`. They did not build it, run Comparator or machine-check any proof. The `sorry` and axiom counts come from a text scan.

## Results (unreviewed)

- **Items (80):** 66 stated faithfully: 50 in a different formulation, 14 Lean stronger, 2 equivalent. 14 with a gap: 7 partial, 6 Lean weaker, 1 absent.
- **Displayed equations (762):** 650 the same, equivalent or Lean stronger (119, 495 and 36). 106 not stated as displayed: 74 by a different formula or route, 31 Lean weaker, 1 absent. 6 not applicable (heuristic or illustrative displays).
- **The preprint** arXiv:2610.08144 (Bastounis, Circelli and Hansen) reports that (8.19) and (10.19) are not what the Lean proves. Both audits agree that neither is stated in the Lean as displayed. The agents' unreviewed tracing of the later uses of both is in [`REPORT.md`](REPORT.md).

Method: two independent agent audits of the items; where they differed, an adjudicator ruled under one rule: stated faithfully only if the paper's statement follows from stated Lean declarations by logic alone. All but 7 of the 762 displays were audited twice, blind; where the two runs disagreed on whether the Lean has the formula, an adjudicator ruled. [`REPORT.md`](REPORT.md) gives the method, the counts and every finding.

## Viewing

```sh
python3 pdf-overlay/tools/serve.py --build   # later runs: omit --build
```

Then open <http://127.0.0.1:8000/pdf-overlay/viewer/index.html> and click a box; "Show faithfulness" adds the verdicts. It needs Python 3.11 or later on macOS or Linux.

On the first run `serve.py` downloads the PDF from its [official URL](https://cdn.openai.com/pdf/32d9f210-8b73-45e0-91bc-82a30aef8a9a/navier-stokes.pdf), checks its sha256 (`0e779481…8ae228f`) and caches it under `.lake/official-pdf/`. It serves on loopback only. The PDF is never committed. To check the generated files, run `python3 pdf-overlay/tools/check_generated.py`.

## Layout

| path | what it is |
|---|---|
| `annotations/<section>/[<item>/]<name>.json` | One record per (item, declaration) and per (display, declaration). The file prefix gives the declaration's role: `key` states the item, `attributed` states a part or a definition, `support` supports it. Fields a folder's records share are in `_defaults.json`. A display that is an item's whole statement, with the item's declarations, has no records of its own. A record with no target is a display that names no declaration, or an item's box continuing onto another page. |
| `pdf-overlay/` | The viewer and its tools, generated by formal-companion's `cf overlay sync`; do not edit. Its `README.md` describes formal-companion's own export, which did not write these annotations. |
| `site/index.html` | The landing page for the local viewer. |
| `REPORT.md` | The report. |

Names `eq-<number>` are numbered equations. In `eq-p<page>-<k>`, k counts every block found on the page, so it can differ from the k of the label "Display <page>.<k>".

`annotations/` and `REPORT.md` are generated from the agents' recorded rulings and the page layout by scripts that are not in this repository; the same scripts write `site/index.html` and `pdf-overlay/overlay.config.json`. The rest of `pdf-overlay/` is written by formal-companion's `cf overlay sync`; `pdf-overlay/GENERATED.json` names the formal-companion commit and the Literature Links commit it used. Only this README is written by hand.
